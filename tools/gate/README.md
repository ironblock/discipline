# Gate
- Skipped is not failed: No path filtering. An aggregator compares each job's result to the literal string `success`; `!failure()` passes on skipped. A filtered-out workflow leaves its required check pending forever.
- The registry is the pin: A gate discovered by globbing can silently find nothing. Required checks are enumerated explicitly at the root.
- Assert on structured failure classes, not message strings: Matching prose is grep-as-verdict one level up; it is why signatures go stale.
- A gate with a build step has a stale-binary axis: Stamp the binary that ran, not the tree's HEAD. Refuse a stale choice rather than pick one. *Specimen: a developer-machine gate graded with a release binary seven days behind the source, lacking a guard the source had carried all week. Four instruments defined a constant named after the environment variable they ignored.*
- Replace hardened instruments by parity, never by patch: The successor is seen red on every seeded fault beside the incumbent before the incumbent retires.
- Changing an instrument invalidates its numbers: Measure before and after; zero rows changed is the receipt.
- Some hygiene is a reviewer's class, not a pattern's (#283): a person's schedule, habits or whereabouts. No pattern can catch free text about when someone uses a machine, so `CONTRIBUTING.md`, the issue and PR templates and the chore brief name it beside the patterned classes, and a reviewer refuses it. A machine's availability is stated as a fact about the machine, never about a person's time. *Specimen: three issue comments explained a box's availability by its owner's days and hours; they were edited the same day.*
- The chore lane changes what an author owes, never what CI runs (#276): every check runs on every pull request. `scripts/pr-scope.py` classifies a diff `material` -- a seeded fault's map reaches it, it changes `verify.sh`, it touches the protocol list or the trees the gate runs from (`GATE_TREES`), both declared in that script, or it touches a root entry other than a Markdown document or a licence, or a root dot-directory, or a top-level Python package or `node_modules/`, or adds, removes or changes a symlink or a gitlink; paths are compared casefolded -- or `chore`, and names the checks the diff touches; a chore's author runs those locally and owes no issue rows, selftest or ruled disclosures. `check_metadata` runs the classifier against its own cases, so a protocol entry it stopped reading goes red.
- A local gate run needs `python3` 3.10 or later first on PATH, and no GNU tools: the sandbox's tree copy is `scripts/copy-tree.py` (#380), and the injections apply under BSD `sed`. A stock Mac's `/usr/bin/python3` is 3.9, which cannot parse the scripts, so a newer one goes first.
- The `ci` check needs `ruby` (#256): rule 10 of `scripts/check-ci-coverage.py` reads `pages.yml` through Ruby's YAML parser, psych. Without `ruby` on PATH the check exits 2 and says so -- a misuse, never a pass -- and `verify.sh` reports `ci (exit 2)` and exits 1. macOS and GitHub's `ubuntu-latest` ship it; the `python:3.12-slim` image does not, so the `ci` check fails that way in that container (track one's run, #258). Review there in an image that carries `ruby`, or run natively.

- An injection is proven to change the tree before its verdict counts: The selftest fingerprints the sandbox either side of an injection and reports one that changed nothing as BROKEN, without running the gate at all, so it already asks the question. `scripts/check-injections.py` asks the same one in seconds rather than in a full run, and on every full `verify.sh` run rather than only under `--selftest`: an inert injection arrives with an edit, and the edit is what should fail. *Specimen: a line-based merge spliced fourteen injection bodies into each other, every one inert; the gate itself stayed green throughout, because a gate does not run its own injections, and the selftest said "`<injection>` changed nothing, so the case proves nothing" fourteen times, fifty-four minutes later.*
- A seeded fault whose check reads git state is measured in a box with no commit, as `sandbox()` builds it: the selftest runs every case in a fresh `git init` with nothing committed, and a measurement taken in a checkout sees a `HEAD` the selftest never will. *Specimen: #217's `check_results` passed `--commit "$(git rev-parse HEAD 2>/dev/null || echo main)"`; with no commit, `rev-parse` prints `HEAD` before failing, the value became two lines, and the renderer refused it -- so both new faults went red without their signatures, though each had been measured red "in a fresh copy" that had a commit.*
- An injection's input is invalid to every future version of both readers, not to the current subset: This is the failure the fingerprint CANNOT see. Growing a format retires the fault while the injection still writes a file, so the pre-flight passes and only the gate's verdict changes. *Specimen: `inject_regimen` wrote `arm = 1.5` to make a regimen.toml not a regimen; four days later the grammar grew floats, the document parsed, and the seeded case reported "the gate did not fire" -- on CI, seven minutes after a push whose local `verify.sh` was green.*
- Resolve the gate files by name, and let the pre-flight choose between two versions of one name: `verify.sh` and `faults.toml` are lists of named blocks, and a conflict hunk is an artifact of where two texts diverged -- git aligns two DIFFERENT injections on the identical boilerplate that opens their heredocs. `scripts/merge-gate.py` rebuilds each file from both sides by name, restores any body that is in neither parent, and where the two parents disagree runs the pre-flight to see which still bites. The red count is DERIVED, never kept (#108): `check-fault-manifest.py` counts it from the assembled list, because base-plus-deltas double-counts whatever both branches inherited by two routes, which a stack of lanes built on each other produces routinely. *Specimen: six of eight lanes carried one body that was in neither parent; a seventh kept an injection whose anchor the other side had moved.*

## `faults.toml` and `faults.d/`
Extracted from the gate, gated in both directions (it can neither omit a proven fault nor claim an unproven one), every fault carrying a `failure_class`, relocated fixtures carrying `migrated_to` with their redness re-proven in the new home.

**Where a new fault's row goes (#383).** A pull request that adds seeded faults or mechanics assertions writes their rows to `tools/gate/faults.d/<ticket>.toml`, named for its ticket's number, a file no other pull request touches. It does not append to `faults.toml`, which every fault-adding pull request used to conflict on. Rules:
- **One set:** `check-fault-manifest.py` and every reader of the table read `faults.toml` and every `faults.d/*.toml` as one set. Row order carries no meaning there.
- **Ids are unique:** an id declared in two places is refused, naming both files.
- **A ticket's second pull request,** while its first is still open, writes `faults.d/<ticket>-<slug>.toml`.
- **Unseedable guards stay in `faults.toml`,** whose `[meta]` still counts them.
- **`[meta]` lives in `faults.toml` alone,** and declares no count that is derived.
- **Permanent:** a per-ticket file is its rows' permanent home, never folded back into `faults.toml` at a release.
- **No hand-kept counts:** `mechanics_assertions` is counted, not kept, and the red count is derived the same way (#108).
- **In `verify.sh`:** put a new case's `inject_*` function and its `seeded_case` or `expect_exit` line beside its own check's cases, not at the end of a list. Two pull requests appending at the same place conflict there.

## The selftest on a pull request, on a push, and nightly
Until the gate redesign the selftest runs on the nightly, the release path and a pull request whose diff touches the selftest's machinery, the events `.github/gate-budget.tsv`'s `selftest_events` names (#369, #398); any other pull request into the integration branch, and a push to it, runs the package checks and no selftest. The nightly, a release pull request and a push to the release branch are `full` runs, proving every fault (`scripts/scope-selftest.py --kind`, #326). A machinery pull request is a `scoped` run, re-proving the faults its diff can reach (#112) -- every one when it changes the selftest's own functions or files, so a long run there is the scope, not a regression. Machinery is `verify.sh` or a file `scope-selftest.py`'s `MACHINERY_FILES` names, decided once, by `pr-scope.py --machinery` in `verify.yml`'s `scope` job; the chore lane and the drift refusal's widening read the same function. Nothing here is harvested or hand-kept.

- A fault's redness is a property of its injection target and its catcher, and a diff that touches neither cannot change it. `scripts/scope-selftest.py` inherits every other fault at the commit where it was last seen red, read from the census of the base branch's newest COMPLETED nightly (#369), and the census declares each one. Nothing is counted as passed without a run. An edit to the selftest machinery re-proves everything, so a mechanics assertion goes in `prove_mechanics` or `prove_selftest_mechanics`, never inline in `selftest`.
- Shards divide the labour, not the list: the plan job packs every fault the newest nightly's census timed, longest first into the emptiest shard, and a hash of the fault's id picks the shard of any fault nothing timed (#319). The census proves every fault ran exactly once, from the ordinals and never from the plan. A scoped run packs from its base branch's census; every other run packs from the default branch's. N is `max_shards` (`.github/gate-budget.tsv`) scaled by the share of faults the run re-proves. The budget is printed on every run, never graded.
- A fault not red on a full run (the nightly, or a push to the release branch) opens one issue per check, labelled `check:<name>`; a pull request's run never opens one. A pull request that touches that check is refused until the issue is closed -- by the `repo` job, on the checks `pr-scope.py` names for its diff, or on every check when the diff is machinery (#369) -- including the pull request that fixes it: close the issue, re-run, and the next full run reopens it if the fix did not hold. A release pull request re-proves every check, so any open drift issue refuses it.
- The superseding rule (#326): a push to the integration branch cancels the run in flight, so merges never queue behind one. Since #369 that run carries no selftest, and the census a full run reads is the newest nightly that completed. A release pull request and a push to the release branch are never cancelled. `verify.yml`'s `cancel-in-progress` is the one expression that says so, and `check-ci-coverage.py` holds it to `.github/branches.tsv`.

## Stage 2: the successor gate
The charter, ruled on the foundation PR and filed as #46. Keep the catch, remove the brittleness: the gate keeps proving every fault red, and the mechanism that keeps breaking -- prose signatures in a monolithic shell script -- is replaced.

- The diagnosis is structural, not incidental: The gates have been stable since the sixth CI run; every later failure was the selftest's own scaffolding. Mutation testing written in shell has no assertions, no fixtures and no structured failure output.
- Dispatch only, in stdlib Python: No build step, so the stale-binary axis disappears for the orchestrator itself. Zero new dependencies. A heterogeneous monorepo does not gate in one of its member languages. The orchestrator parses **only its own manifest format**; every program format is `diet check-*` through the resolver, with the binary path and its SHA-256 stamped in the run.
- Declare a check beside the code that emits it: A per-package `gate.toml`, so a package changes its own behaviour without editing the root -- and a root registry pinning which manifests must exist, because a gate discovered by globbing can silently find nothing.
- Assert on the class, never on the text: Every check emits `check`, `status`, `failure_class`. Changing a message must not break the selftest; changing a failure class must. This covers the harness and not only the checks: mechanics assertions are class-asserted and the scaffolding becomes a `unittest` suite whose own failures are typed. *Specimen: five stale message signatures, each caught, each requiring a fix in the root script for a change made in a package it does not own.*
- Migrate by parity per failure class, not per script: Every fault in `faults.toml` maps to a reproducing successor fault or a `migrated_to` naming the conformance fixture that replaces it. Relocated fixtures are re-proven red in their new home. `verify.sh` is deleted only in the change that shows the successor red on every fault.
- The hermetic sandbox is kept, not rebuilt: An allowlisted environment with stated reasons, `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` isolated, checks that read the environment tested under a faked one, and the injection pre-flight in the critical path. *Specimen: a sandbox inherited the runner's environment and read red while proving nothing.*
- The assembled stack is the truth: Per-branch fault counts are partial by construction -- nine lanes added faults independently and they reconciled only at assembly. `merge-gate.py` reconciles them; a count from one branch is not a number about the gate.
